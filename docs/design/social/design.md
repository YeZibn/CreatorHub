# 社交模块设计

[架构总纲](../../../ARCHITECTURE.md) · [数据库设计](database.md) · [API 设计](api.md) · [关系首页缓存](cache.md) · [关注关系主规格](../../../openspec/specs/user-follows/spec.md)

首期单向关注 API 已实现并通过本地验收。用户可以关注、取关、查询自己的关注状态，以及浏览本人的关注和粉丝列表。验收使用已知用户 ID，用户搜索和公开作者入口留到后续。

## 关系与权限

A 关注 B 形成一条 `A → B` 关系。A 的关注列表和 B 的粉丝列表读的是同一条关系。B 关注 A 时形成另一条关系，A 取消关注 B 后，B 对 A 的关注仍然有效。

- 操作者和列表所有者均来自服务端的[身份认证上下文](../identity/design.md#模块边界)。路径 ID 只指定目标，分页游标只限定读取位置。
- 建立关注时，目标必须是存在且状态为 `ACTIVE` 的其他账号。既有关系按表中记录查询，目标停用后仍可取关。
- 列表仅返回对端的用户 ID、昵称和关注时间。昵称从身份模块的资料表读取，列表和状态响应使用 `Cache-Control: no-store`。

## 实现边界

| 位置 | 职责 |
| --- | --- |
| `creatorhub-api` | `FollowController` 提取会话身份、校验目标和游标，处理 HTTP 响应与错误 |
| `creatorhub-core` | `FollowService` 管理写入事务，`FollowMapper` 执行关系查询和写入，由 `FollowSummary` 承载列表摘要 |
| MySQL 与 Redis | MySQL 保存当前关系并裁决并发插入，Redis 提供现有登录会话 |

以 A 关注 B 为例，Controller 使用 A 的会话身份调用 Service。事务内检查 B 的账号状态并插入关系，同一方向的重复写入保留原关注时间。事务提交后返回 `204`，后续 A 的关注列表与 B 的粉丝列表即可读取这条关系。并发取关与关注的最终状态取决于数据库实际执行顺序，客户端遇到超时可查询当前状态，再按用户最新意图操作。

## 关系首页缓存

已实现并通过本地验收，缓存读取默认关闭。缓存覆盖「我的粉丝」和「我关注的人」的首页。续页和单条关注状态由 MySQL 查询。Controller 继续解析会话和原分页参数，`creatorhub-core` 负责事务、版本、回源及昵称拼装，`creatorhub-infrastructure` 提供 Redis 客户端、超时配置和 Lua 执行。

A 关注或取关 B 时，实际关系变动只影响 A 的关注列表与 B 的粉丝列表。MySQL 在写关系的同一事务中更新这两个方向的列表版本。提交后开始的首页请求读取主库的新版本，因此即使先前的查询较晚回填，旧名单也只会进入旧版本的 Redis key。[版本表和写入事务](database.md#列表版本表与迁移) · [缓存读取、回填与故障](cache.md)

本阶段的验收覆盖关系正确性、旧快照延迟回填、缓存回源以及高并发的读写代价。首页推荐、共同关注、粉丝计数与 Feed 分发各自设计。

## 发布分发与 CDC

粉丝索引支持按作者 ID 分页查询当前候选接收者。[文章发布与按 ID 阅读](../content/design.md#文章发布与阅读)已独立交付。发布时是否固定受众、发布后取关如何影响尚未完成的分发，以及是否回填历史文章，留到 Feed 阶段确定。

当前 [Compose](../../../compose.yaml) 的 Canal 白名单只包含 `cdc_smoke_probe`。私有草稿和关注关系均保存在 MySQL，关系的建立与删除不会进入 Kafka。后续若开启业务表采集，先明确事件字段、消费方、顺序及恢复机制。部署已有环境时，按[本地运行说明](../../../README.md)确认运行中的 Canal 已应用白名单，再开放关系写入。

## 本地验收记录

| 场景 | 已验证的结果 |
| --- | --- |
| 认证与权限 | 未登录请求返回 `401`，缺少有效 CSRF Token 的写请求返回 `403`。自关注、伪造操作者和不可关注目标被拒绝 |
| 关系竞争 | 12 个并发关注请求只产生一条关系，重复关注保留原时间，重复取关成功，反向关系独立 |
| 列表分页 | 同毫秒关系按对端 ID 稳定跨页。跨账号游标仍由当前会话限定，两个列表之间错用游标返回 `400` |
| 升级与 CDC | V2 升级至 V3，两个方向的首页及续页均命中各自索引。同一 Kafka 分区收到了独立验证标记，观察区间内没有关注或草稿行事件 |

身份和草稿 API 也通过回归。具体验收项见 [OpenSpec 归档任务](../../../openspec/changes/archive/2026-11-20-add-user-follows/tasks.md)。
