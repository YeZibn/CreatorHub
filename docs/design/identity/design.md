# 身份与账号模块

本轮确认四项能力：注册、登录、退出、修改本人昵称。`GET /me` 为页面刷新和验收提供当前用户查询。第一版面向本地演示，注册成功后账号直接可用，由用户单独登录。公开注册前再设计邮箱验证。改密、找回密码和头像随对应功能追加。

## 模块边界

每个用户用同一个稳定的 `userId` 表示，可以阅读和创作。对受保护的请求，Java 从 Spring Security 的认证上下文取得当前 `userId`。客户端提交的路径、查询和请求体字段只能指定操作目标，不能指定操作者。修改昵称时，目标也由会话身份确定。

MySQL 保存账号、凭证和资料。Redis 保存服务端登录会话，浏览器持有会话 ID Cookie。账号表和资料表不加入内容 CDC 白名单。字段、关系和迁移顺序见[数据库设计](database.md)，可见字段及请求契约见 [API 设计](api.md)。

## 关键流程

1. **注册。** 校验邮箱、密码和昵称，使用 Argon2id 生成密码哈希。在同一 MySQL 事务中创建账号及资料，提交后返回成功。邮箱同时被注册时，以唯一约束裁决。
2. **登录。** 用规范化邮箱查询账号，校验密码和账号状态。认证成功后轮换会话 ID，并通过 Spring Session 将认证上下文存入 Redis。会话可供不同 API 实例读取。登录会话缺失或过期时，当前用户接口返回未认证。
3. **退出。** 撤销 Redis 中当前浏览器使用的会话并清理 Cookie，其他设备继续使用各自的会话。撤销完成后的新请求不能用旧 Cookie 恢复身份，已经通过鉴权的在途请求可能完成。
4. **改昵称。** 用会话中的 `userId` 定位资料行，按约定校验后更新。事务提交后返回该用户的新资料。

## Java 代码归属

| Maven 模块 | 负责的内容 |
| --- | --- |
| `creatorhub-api` | `AuthController`、`CurrentUserController`、HTTP DTO、Spring Security、Cookie、CSRF 与 Spring Session |
| `creatorhub-core` | `identity` 下的 `AccountService`、`UserProfileService`、账号和资料的 Entity、Mapper 与 SQL XML |
| `creatorhub-infrastructure` | 共享 Redis 连接配置 |

## 实现顺序与验收

| 步骤 | 可观察的结果 |
| --- | --- |
| 先用 A、B 两个测试账号跑通登录、`/me` 和退出 | 两个 Cookie 各自返回正确用户。同一个 Cookie 在两个 API 实例上都可用。登录前的会话 ID 无法获得登录身份。退出后旧 Cookie 在两个实例上都返回 `401`，另一设备的会话仍有效 |
| 接入注册 | 并发提交同一个规范化邮箱时，最终只存在一个账号和一份资料。资料创建失败时，账号插入一起回滚 |
| 接入改昵称 | A 可以改自己的昵称。请求携带 B 的 ID 时返回参数错误，A、B 的资料保持不变。普通修改后 B 的资料也保持不变 |

这些是待验证的验收条件。会话超时阈值和 Argon2id 参数在实现时配置并验证。
