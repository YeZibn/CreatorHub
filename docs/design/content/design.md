# 内容模块设计

[架构总纲](../../../ARCHITECTURE.md) · [数据库设计](database.md) · [API 设计](api.md)

私有草稿 API、Vue 编辑器、作者发布和登录用户阅读 API 已实现。作者隔离、发布竞争、CDC 边界和身份回归均通过本地验收。

## 首期范围

创作者登录后，可新建、查看、分页浏览和手动保存 Markdown 草稿。草稿行有稳定的内容 ID。作者发布时沿用该 ID，将同一条记录由 `DRAFT` 改为 `PUBLISHED`。

| 层面 | 职责 |
| --- | --- |
| Vue | 展示个人草稿列表和编辑器，提交用户手动保存的内容，处理会话失效、保存失败和版本冲突 |
| `creatorhub-api` | MVC Controller 从 [身份认证上下文](../identity/design.md#模块边界)取得 `userId`，校验 HTTP 请求，返回草稿数据或错误 |
| `creatorhub-core` | 内容 Service 管理草稿与发布事务，MyBatis Mapper 执行包含作者、状态和版本条件的查询与更新 |
| MySQL 与 Redis | MySQL 保存草稿和已发布文章并裁决写入竞争。Redis 提供已有的登录会话 |

## 编辑流程

1. **打开工作台。** 使用当前会话加载草稿摘要。打开已有草稿时，再读取正文和版本。刷新已有草稿的编辑页时，按 ID 重新请求详情并校验归属，恢复最后一次成功提交的版本。
2. **首次保存。** 点击「新建草稿」只打开空白编辑器。点击保存时提交标题和正文。事务提交后，编辑器用响应中的 ID 和版本建立编辑状态，并刷新列表。
3. **后续保存。** 提交更新时携带打开草稿或上一次保存成功获得的版本。一个页面同一时间只发起一次保存。成功后以服务端返回的新版本为准。
4. **冲突与超时。** 收到 `409` 时保留当前输入，暂停保存，提示作者主动重新加载。重新加载成功才替换输入。网络失败或超时时保留输入，不自动重试。创建请求若在提交后丢失响应，可先回列表确认是否已创建。会话失效时返回登录界面，重新登录后按当前账号加载草稿。

## 文章发布与阅读

作者可以发布自己的草稿。登录用户可按 ID 阅读任何已发布文章。下架、已发布文章编辑、匿名阅读和 Feed 分发留待对应阶段设计。

1. **发布同一条内容。** 作者提交已保存草稿的 ID 和草稿版本。服务端使用会话身份确认归属，检查草稿状态、版本和已保存的标题及正文。草稿仍允许只填一项，发布时两项都须包含非空白字符。
2. **提交后可读。** 事务将该行从 `DRAFT` 切换为 `PUBLISHED`，成功提交后才返回。文章保留原 ID，草稿列表和草稿详情仅匹配 `DRAFT`，文章详情仅匹配 `PUBLISHED`。
3. **登录用户阅读。** 任何登录用户均可按 ID 读取已发布文章。关注关系影响后续 Feed 的受众计算，文章详情按发布状态授权。草稿 ID 通过文章详情查询时统一返回 `404`。

两个标签页同时发布只会发生一次状态转换。保存与发布竞争时，数据库行锁串行化两笔操作。若保存新版本先提交，旧版本发布返回 `409 CONTENT_VERSION_CONFLICT`。若发布先提交，草稿更新按原规则返回 `404 DRAFT_NOT_FOUND`。作者以首次发布的草稿版本重试时，返回同一篇文章、版本和首次发布时间，不重复写入。细节见[发布事务与重试](database.md#发布事务与重试)及[API 契约](api.md#发布与阅读接口)。

## 作者隔离与 CDC

每次详情、列表及更新都在 SQL 中限制 `author_id = 当前会话用户 ID` 和 `status = 'DRAFT'`。路径 ID 只定位目标，游标只表示分页边界。草稿接口使用 `Cache-Control: no-store`，正文不写入业务日志，也不写入浏览器持久化存储、业务缓存或 Feed。

当前 [Compose](../../../compose.yaml) 的 Canal 白名单仅包含 `cdc_smoke_probe`。草稿和发布阶段沿用该配置，因此写入及状态转换不会进入 Kafka。MySQL 使用完整行镜像，进入 Feed 分发阶段后，建议另行设计发布事件，继续排除同时存有草稿的 `content` 表。发布之后、分发之前取关是否影响接收资格，留到[发布分发设计](../social/design.md#发布分发与-cdc)确定。

## 验收

| 场景 | 可观察结果 |
| --- | --- |
| A 新建并重新打开草稿，B 使用 A 的 ID 读取或写入 | A 能读到原文，B 的详情和更新均返回 `404`。B 的列表始终只包含 B 的草稿 |
| 两个标签页用同一版本保存不同正文 | 一个返回 `200` 并增加版本，另一个返回 `409`。失败标签页保留输入，主动重载后才显示胜出的正文 |
| 同一作者的多条草稿具有相同毫秒时间戳 | 在无并发写入时跨页逐条出现一次。首页与后续页的 `EXPLAIN` 均检查 [联合索引](database.md#索引与分页) |
| 草稿 CDC 验收 | 记录 Kafka 分区起始位点，创建和更新带唯一测试标记的草稿，再写入 `cdc_smoke_probe` 的独立标记。从同一分区读到后者，并确认区间内没有 `content` 行事件或草稿标记 |
| 发布和读取 | A 无法代替 B 发布草稿，读者在发布前收到 `404`，发布后使用同一 ID 读取成功。是否关注作者不影响阅读 |
| 发布校验与重试 | 标题或正文为空白时发布失败且草稿保留。作者以原草稿版本重试得到同一发布时间，其他版本收到 `409` |
| 并发保存与发布 | 同一草稿的编辑和发布按提交顺序串行化。只允许一笔完成，另一笔获得版本冲突或草稿不存在响应 |
| 发布 CDC | 创建、编辑及发布后，同一 Kafka 分区收到了独立验证标记，观察区间内没有内容行变更或发布事件 |
