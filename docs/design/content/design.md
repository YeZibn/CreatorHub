## 首期范围

创作者登录后，在「我的草稿」新建、查看、分页浏览和手动保存 Markdown 草稿。第一期只有 `DRAFT` 状态，创建时产生稳定的内容 ID。后续发布沿用这个 ID，发布、下架、删除、公开阅读、自动保存和 Markdown 预览随对应阶段设计。

| 层面 | 职责 |
| --- | --- |
| Vue | 展示个人草稿列表和编辑器，提交用户手动保存的内容，处理会话失效、保存失败和版本冲突 |
| `creatorhub-api` | MVC Controller 从 [身份认证上下文](../identity/design.md#模块边界)取得 `userId`，校验 HTTP 请求，返回草稿数据或错误 |
| `creatorhub-core` | 内容 Service 管理事务，Entity 表示草稿数据，MyBatis Mapper 执行包含作者和状态约束的查询与更新 |
| MySQL 与 Redis | MySQL 保存草稿并裁决版本竞争。Redis 提供已有的登录会话。单条草稿的并发保存由 MySQL 条件更新保证 |

## 编辑流程

1. **打开工作台。** 使用当前会话加载草稿摘要。打开已有草稿时，再读取正文和版本。刷新已有草稿的编辑页时，按 ID 重新请求详情并校验归属，恢复最后一次成功提交的版本。
2. **首次保存。** 点击「新建草稿」只打开空白编辑器。点击保存时提交标题和正文。事务提交后，编辑器用响应中的 ID 和版本建立编辑状态，并刷新列表。
3. **后续保存。** 提交更新时携带打开草稿或上一次保存成功获得的版本。一个页面同一时间只发起一次保存。成功后以服务端返回的新版本为准。
4. **冲突与超时。** 收到 `409` 时保留当前输入，暂停保存，提示作者主动重新加载。重新加载成功才替换输入。网络失败或超时时保留输入，不自动重试。创建请求若在提交后丢失响应，可先回列表确认是否已创建。会话失效时返回登录界面，重新登录后按当前账号加载草稿。

## 作者隔离与 CDC

每次详情、列表及更新都在 SQL 中限制 `author_id = 当前会话用户 ID` 和 `status = 'DRAFT'`。路径 ID 只定位目标，游标只表示分页边界。草稿接口使用 `Cache-Control: no-store`，正文不写入业务日志，也不写入浏览器持久化存储、业务缓存或 Feed。

当前分支的 [Compose](../../../compose.yaml) 仍在 Canal 白名单中订阅 `content`。重新开放草稿写入前，先移除该表并核对运行中实例的过滤规则，保留 `follow` 和 `cdc_smoke_probe`。MySQL 继续使用现有的完整行镜像配置。发布阶段需先定义发布事件和私有字段边界，再决定内容变更如何分发。

## 验收

| 场景 | 可观察结果 |
| --- | --- |
| A 新建并重新打开草稿，B 使用 A 的 ID 读取或写入 | A 能读到原文，B 的详情和更新均返回 `404`。B 的列表始终只包含 B 的草稿 |
| 两个标签页用同一版本保存不同正文 | 一个返回 `200` 并增加版本，另一个返回 `409`。失败标签页保留输入，主动重载后才显示胜出的正文 |
| 同一作者的多条草稿具有相同毫秒时间戳 | 在无并发写入时跨页逐条出现一次。首页与后续页的 `EXPLAIN` 均检查 [联合索引](database.md#索引与分页) |
| 草稿 CDC 验收 | 记录 Kafka 分区起始位点，创建和更新带唯一测试标记的草稿，再写入 `cdc_smoke_probe` 的独立标记。从同一分区读到后者，并确认区间内没有 `content` 行事件或草稿标记 |
